**Figure 1. vepyr architecture, cache organization, validation and performance.**
**(A1)** Annotation dataflow from indexed VCF through the Rust/DataFusion engine to streaming Arrow batches, annotated VCF or a Polars LazyFrame. The dashed return denotes lazy query demand: selected columns, supported genomic predicates and limits can reduce annotation work; annotation-derived predicates filter the resulting batches.
**(A2)** Conversion of the Ensembl VEP cache into entity- and chromosome-partitioned Parquet. A separate inset shows CADD plugin provenance in its JSON manifest, including the requested ref and resolved commit, source URLs and declared/verified checksums. This cache-level sidecar is distinct from the row-level provenance columns carried by core context entities. Plugin shards inherit variation tiers.
**(A3)** Magnification of a variation chromosome shard: typed lookup keys, encoded payload, file identity metadata, warm/cold sorted runs, row groups, leaf-column chunks and indexed pages. Warm positions are selected by maximum global AF ≥ 1%, with a one-base neighborhood; both tiers remain queryable. Tier boundaries need not align with row groups, and warm/cold here does not describe OS page-cache state. Lookup resolves candidate pages, locates rows and retrieves projected payload. Shown settings are current point-lookup writer defaults (one-million-row group cap, ZSTD 3, dictionary encoding off, 4 KiB/512-row page targets), not guaranteed realized sizes or historical benchmark-cache settings. Context entities instead use a 50,000-row cap and dictionary encoding; parameter-sweep results remain pending.
**(B)** Component-level unit tests, ported VEP behavior fixtures and end-to-end comparisons across six release/source profiles. Each archived field gate covers 4,096,123 HG002 autosomal variants and reports zero CSQ-field mismatches. The harness also supports separate strict/canonical VCF-body MD5 checks.
**(C)** Preliminary single-run Linux scaling on HG002 GRCh38 chromosomes 1–22 using the release-116 merged cache, `--everything` and HGVS. At eight forks/workers, process wall times are 6,326 s for VEP and 187.67 s for vepyr (33.7-fold). Paired macOS whole-genome and equivalent filtering measurements are placeholders; replicated comparisons remain pending.
**(D)** Input/output contracts and equivalent whole-variant rare-or-unknown AF predicates in `filter_vep` and Polars SQL. Consequence-level predicates require explicit list handling. Structural-variant parity and cohort-scale multisample parity are outside the current qualification gate.
