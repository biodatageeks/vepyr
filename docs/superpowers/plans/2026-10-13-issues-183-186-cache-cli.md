# Issues 183–186: cache builder and CLI validation

## Defects and triggering inputs

This group fixes misleading or unsafe behavior at vepyr's public cache-building and CLI boundaries. Issue #183 passes a valid but incorrect `cache_type` (for example `refseq` for a raw `homo_sapiens/116_GRCh38` cache), allowing output metadata and the output directory name to misdescribe the data. Issue #184 explicitly requests a contig absent from the raw cache (for example `--chrom 7` when only chr22 is present), and the build succeeds with an empty manifest. Issue #185 re-runs a plugin cache build for an existing shard without `--overwrite`, rewriting the shard and potentially leaving provenance inconsistent. Issue #186 covers duplicate `--verify_source warn` output, a missing plugin source reported as its `.tbi`, and a missing annotation cache reported as a missing manifest.

## Repository ownership and one-PR scope

The exact vepyr dependency pins are `datafusion-bio-formats` `72efe677985eca4092e0c20753976dbe45d94032` and `datafusion-bio-functions` `b960112c43a68eef564d117fe49711eb99c089a6` (Cargo.lock). Formats carries the requested source type into schema metadata but does not validate the raw cache identity. Functions owns raw cache type and contig validation, plugin shard overwrite behavior, source/index error ordering, and the generic missing-cache diagnostic; its plugin builder explicitly rebuilds requested shards. Vepyr owns CLI warning duplication and can validate inputs at its public API boundary.

To satisfy the request for one PR, the proposed change is vepyr-only. It will validate raw-cache identity and requested contigs before calling the native builder; preserve existing plugin shards and reject incompatible manifest versions before invoking the native builder; check plugin source and annotation cache paths before handing them to the engine; and format the `warn` mode once. The tests will exercise vepyr's Python API and CLI so users of vepyr receive the expected behavior. Direct callers of `datafusion-bio-functions` remain outside this PR's scope. No upstream pins should move.

## Failing tests and coverage

Add focused tests to `tests/test_build_cache.py`, `tests/test_build_plugin_cache.py`, `tests/test_cli_build.py`, and `tests/test_annotate.py`:

- An Ensembl raw-cache fixture requested as `refseq` raises before output/manifest creation; the correct cache type remains accepted.
- An explicit missing contig raises with the missing name before any manifest is written; an available contig remains accepted.
- Rebuilding an existing plugin shard without `overwrite` leaves its bytes/mtime unchanged and reports that it was kept; a requested version change cannot silently mix with untouched shards. With `overwrite`, rebuilding proceeds.
- CLI warn mode emits one warning; a nonexistent plugin source names the source path; annotation against a nonexistent cache reports the cache directory.

Existing tests cover cache-type forwarding, invalid types, a valid raw-cache build, full plugin-cache overwrite refusal, and warning emission from the Python API. They do not cover valid-but-wrong source types, absent requested raw contigs, preservation of an existing filtered plugin shard, duplicate CLI warning formatting, source/index error precedence, or a missing annotation cache directory. These synthetic fixtures can reproduce the reported inputs without the large WGS corpus.
